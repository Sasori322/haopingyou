#### 跨姿态尺度校准（暹罗猫这轮的经验，下次出新宠物直接照做）

三个身体形变族（站立 / 趴卧 / 悬空）用**同一张定妆照做图生图**，源图尺度天然一致，
拿一个统一系数换算即可。**走路族必须逐帧单独出图，源图尺度与其它族对不上**，
必须反推系数——而这正是最花时间的一步：**离线指标全都不可信**。

实测同一只暹罗猫，走路族源图相对站立族的倍率：

| 指标 | 得出倍率 | 为什么不可信 |
|---|---|---|
| 描边粗细 | 1.75 | 取「边缘第一段深色游程」，扫到深色尾巴/爪子就误判。**对照族（悬空 vs 站立，本应 1.0）量出 8 vs 19px** |
| 颈部收窄法量头高 | 1.74 | 横身姿势下颈部检测失效——量出头宽 = 内容宽的 98%，说明量到的是**身体长度**不是头 |
| 蓝眼像素面积 | 1.52 | 3/4 视角远眼被遮挡，面积被低估 |
| 蓝眼**竖直高度** | 1.42 | 正脸眼是**横椭圆**、侧视眼是**圆**，造型本身就不同，不能当不变量 |
| 粉色内耳高度 | 1.62 | 对照组 0.95（应 1.0），本身带 5% 视角偏差 |

**结论：离线指标只适合"同视角内的帧间对齐"（`equalize-frames` 的用途）；跨姿态的绝对尺度只能看真实渲染。**
落地做法：新增 `HPY_FORCE_STATE=<状态>` 自检钩子把宠物钉在指定状态，配合 `HPY_CAPTURE_PET`
逐族截图——窗口尺寸固定，并排一比就是用户视角。暹罗猫走路族最终取 `--scale 0.445`（三个候选值
0.396 / 0.445 / 0.483 实测对比后选定），此时走路内容高 178 DIP ≈ 站立 176 DIP。

**顺带一个出图侧的经验**：悬空族按小橘猫的画法，竖向外框会到站立的 1.43 倍（就是「拎起来膨大一圈」的元凶）。
暹罗猫初版曾在出图 prompt 里要求「四肢收拢、尾巴盘到身侧、不得竖向拉伸」，成品只有站立的 1.05 倍——
但用户实测反馈**读不出"被拎起来"**（看着像坐着），2026-10-14 晚已按橘猫式悬挂姿态重做：
纯文字出悬挂姿 → 形象迁移 → 一张图扩 4 帧摆动，`--scale 0.66`，内容高 251 DIP 与橘猫拖拽（251）对齐。
「出图时解决比例」的经验仍然成立，但**前提是姿态本身符合用户预期**——压缩过头会把"拎起来"压没。

#### 出图路线（2026-10-15 重做暹罗猫后的现行结论，下次出新宠物照做）

AI 生成 + 自写零依赖流水线；原素材放 `.workbuddy/artwork/<petId>/`（不进打包）。

| 结论 | 说明 |
|---|---|
| ⚠️⚠️ **不要单次生成「多格条带」** | 实测四格条带里的猫明显比定妆照瘦长，再补 image2 锚点也救不回。**正确做法：每个姿态独立生成「单只猫单帧」**，形象与定妆照高度一致，再配程序化微动出 4 帧 |
| ⚠️ **四肢换位类（walk / 奔跑）必须逐帧出图** | 单次生成条带即使 prompt 把对角步态相位逐腿写死，**后腿仍会锁死**（实测后半身仅摆动 4.2px）。现行路线 = **旧走路单帧当 image1（管姿势）+ 新定妆照当 image2（管形象）**，实测后半身 21.9px / 前半身 15px。跨帧色漂**不靠单次生成**，用程序化逐帧 harmonize 拉齐 |

### 3. 鼠标跟随 + 沉浸躲开

| 功能 | 状态 | 关键实现 |
|---|---|---|
| **鼠标跟随** | ✅ | 主进程 60ms 采样 `screen.getCursorScreenPoint()`（渲染层拿不到全局光标：窗口是穿透的）；按"窗口水平中心 + 高度 30%"为观察点算方向，按感知半径做距离衰减，**量化到 1/16 并去重后才发 IPC**；渲染层 rAF 平滑后映射为最多 **5px 位移 + 2.2° 倾斜**，**收敛即停 rAF**（常驻 rAF 会一直满帧唤醒）；站立族状态（idle/click/eat/rest/hot/focus）下按光标方位翻转朝向，**走动中仍以走动方向为准** |
| **沉浸时自动躲开** | ✅ | 三条触发器：① 名单进程在运行 ② 前台窗口铺满整屏 ③ 手动安静（30 分钟 / 1 小时 / 现在回来）。任一成立**持续 1.5s** 才隐藏，条件消失同样延迟 1.5s 恢复（没有这个防抖，alt-tab 会让宠物反复闪） |
| **可见性不覆写用户意图** | ✅ | 隐藏是"临时隐藏"；恢复时读的是 `settings.petVisible` 而不是无脑 `true`。用户主动把宠物唤出后有 5 分钟豁免窗口，否则下一个 tick 又会被自动藏回去（表现为"点了没反应"） |
| **前台窗口探针** | ✅ | 常驻一个 PowerShell 辅助进程读前台窗口矩形 + 名单进程命中。**不用 Add-Type、不编译任何 C#**（企业策略常拦），纯反射载入系统程序集。实测：程序集载入 12.7ms、首次查询 95ms、**稳态每次 1–2ms**；进程名单走 `Get-Process -Name`，**不枚举全表**（`tasklist` 实测 530–700ms/次，不能用） |

**附带修掉的两个坑**：① 辅助进程脚本必须是**全 ASCII** 并通过 `-EncodedCommand`（base64 UTF-16LE）传入——中文写在 `.ps1` 里会被 PowerShell 5.1 按 GBK 读串，直接语法错误；② 进程名单会被拼进 PowerShell 脚本，是**注入面**，所以在 `sanitizeSettingsPatch` 里把字符集收紧到 `[a-z0-9._*?-]`、最多 8 项。

**实机验证结论（2026-10-14）**

| 场景 | 期望 | 实测 |
|---|---|---|
| 名单进程出现 | 1.5s 后隐藏 | ✅ `沉浸躲开 → 正在运行 ping · 窗口可见：false` |
| 进程退出，用户意图 = 显示 | 1.5s 后恢复 | ✅ `沉浸结束，恢复显示（用户意图： true · 窗口可见：true）` |
| 进程退出，**用户意图 = 隐藏** | **保持隐藏** | ✅ `沉浸结束，恢复显示（用户意图： false · 窗口可见：false）` |

第三条是最关键的安全不变量——用户主动关掉的宠物不能被"带"回来。另有独立旁证：隐藏后跟随采样立即归零（`gazeWatcher` 有 `!win.isVisible()` 早退），说明窗口是**真的不可见**，不是"以为藏了"。
仍未实测的是**全屏检测**这条触发路径（判定逻辑与探针稳态耗时已单独验证，但没在真全屏应用里跑过一轮）。

**顺带加的开发期自检**：`HPY_OPEN_SETTINGS=1 npm run dev` 会自动打开设置窗口、把渲染层 console 转发到主进程日志、并**逐个路由** dump DOM 证据（页面标题 / 卡片名 / 设置行数 / 正文长度）后退出——设置页唯一入口是托盘菜单，手工路径太长，而"页面空白"和"只是没数据"在日志里长得一样。实测 `/pet` 3 张卡片 8 行、`/general` 6 行、`/pomodoro` 3 卡片 10 行，其余页面均有正文，**无空白页**。

### 4. 提醒底座 + 久坐 / 喝水提醒

先说一个结构性事实：**番茄钟、久坐、喝水、待办的截止提醒，四件事的触发条件完全不同，
但"怎么把提醒送到用户面前"完全一样**。所以先做了投递层，再在上面挂功能——否则就是同一段逻辑抄四遍，
而且"免打扰""沉浸时别打扰"这种横切规则必然漏掉某一处。

| 功能 | 状态 | 关键实现 |
|---|---|---|
| **提醒投递层** | ✅ | **宠物气泡优先，系统通知只在"说不了"时兜底**。为什么不出系统通知：通知头顶那行**应用署名**由 Windows 按 AUMID 解析，粒度是"应用"而非"通知"，**改不成宠物名**（dev 态回落成 `Electron`，打包后是好屏友），弹出来像第三方弹窗、还和气泡重复打扰。兜底触发条件有两条：① 宠物被用户藏起来（气泡发了也看不见）② 该提醒类型没有气泡台词（如尚未接线的番茄钟）。**系统通知这一路不能删**——托盘提示要用户主动看，宠物藏起来时它是唯一会自己冒出来的通道。通知标题统一加**宠物昵称前缀**（实际看到的是「小可 · 该喝水啦」），昵称口径走 `petApp.displayName`（用户自定义名 → manifest 的 `nickname` → 品种名）。⚠️ 代价：正常提醒**没有提示音**，全项目唯一的发声源就是系统通知的 `silent: false` |
| **久坐提醒** | ✅ | 只统计**连续活跃**时间：`activeSince` 存绝对时间戳，坐多久 = `now - activeSince`。离开座位靠 `powerMonitor.getSystemIdleTime()` 超过 `sedentary.idleMinutes` 判定，中断累计 |
| **喝水提醒** | ✅ | 存**绝对** `nextWaterAt`，到点即触发。座位空着时不弹也**不推进排程**——用户回来会立刻收到一次，而他确实该喝水了 |
| **免打扰** | ✅ | 托盘与宠物右键菜单各一个入口。**丢弃不补发**：用户点"免打扰 1 小时"是明确意图，一小时后不该被攒下来的旧提醒炸一遍 |
| **沉浸期间挂起** | ✅ | 宠物已自动让路（游戏/全屏）时不弹，**挂起到沉浸结束再补一次**。只保留最近一条——攒一堆旧账回来一起弹同样是打扰 |
| **运行状态可见** | ✅ | 设置页「专注与提醒」显示：已连续活跃多久 / 目标、是否判定离开、下次喝水提醒时刻、免打扰倒计时、最近一次提醒。提醒最短验证周期有 5 分钟，只能靠等待，所以必须把主进程里的实时状态摊出来 |

**为什么两条时间都要存绝对时间戳**：`setInterval` 在系统休眠、CPU 满载时会漏拍漂移，
累加出来的"坐了多久"会越来越不准。存时刻则永远精确，tick 只负责"来检查一下到没到点"，迟到了也不累积误差。

**久坐离开判定的已知误差（有意不修）**：判定的粒度就是 `idleMinutes` 本身——用户离开后要等空闲涨到阈值
我们才知道，所以离开前最多 `idleMinutes` 的那一段会被误算成活跃。3 分钟量级的误差放在 45 分钟的尺度上无所谓，
不值得为它引入"回填上次活动时刻"的复杂度。

**实机验证结论（2026-10-14，用 `HPY_FAST_REMIND=1` 把阈值压到秒级）**

| 场景 | 期望 | 实测 |
|---|---|---|
| 久坐到点 | 到点提醒 | ✅ 每 20 秒投递一次（加速），气泡每次换一句 |
| 喝水到点 | 到点提醒 | ✅ 每 25 秒投递一次（加速） |
| 离开座位 | 中断累计 | ✅ `判定离开座位（已空闲 12s），久坐计时中断` |
| 免打扰 | 真的不弹 | ✅ `丢弃提醒：sedentary` / `丢弃提醒：water`，且独立确认 28 秒内无新提醒落地 |
| 免打扰恢复 | 是丢弃不是吞掉 | ✅ 恢复后 4 秒内收到提醒 |
| 沉浸期间 | 不打扰 | ✅ 6 次提醒全部延后 |
| 沉浸结束 | 补发且只补一条 | ✅ 6 次延后 → 补发 **1** 次，宠物状态与气泡正确恢复 |

### 3. 已知缺口（不是新功能，但更该先补）

- **宠物位置不持久化**：重启后回到主屏右下角，也没有"回地面"的快捷入口。
- **宠物缩放上限就是 100%（`PET_SCALE_MAX = 1`）**：窗口尺寸按 `canvas + 20` 固定推算，**不随缩放放大**，
  而悬空挣扎那族最高（站立姿的 1.43 倍），所以放开到 1 以上时最先顶出窗口的就是它——
  表现为「拎起来的瞬间爪子/尾巴尖被窗口边缘切掉」。已在设置页滑块与主进程校验两处都夹到 `[0.5, 1]`，
  并在读取出口对旧配置里残留的超限值做一次收敛。
  **想真正支持放大，前提是先让窗口尺寸随 scale 一起长并按最高姿态族计算**，那是独立的一件事。
- **悬空姿态观感偏大**：竖直外框是站立的 1.43 倍（同一只猫、头一样大，只是躯干竖直 + 长尾巴下垂），
  叠加"底边对齐 + 固定窗口"，被拎起来时占窗高会从 63% 弹到 90%。要改得**重画姿势**（尾巴收起来），
  而不是缩放（缩放会让头身尺寸和其它状态不一致）。
- **任务栏自动隐藏时全屏检测会跳过**：那种设置下"最大化"与"真全屏"的窗口矩形完全一样，无法区分，
  此时不下判断，宁可漏判也不误判（误判会让宠物在工作时莫名消失）。
- **未打包运行时 Windows 通知可能不显示**：开发环境常常没有开始菜单快捷方式，系统通知会静默失败。
  这正是提醒要坚持"三路并行"的原因——两条路都断了才会真正漏掉提醒。
  代码里会在 `Notification.isSupported()` 为假时打一条告警，实机不能只靠通知来判断功能有没有生效。
- **提醒只在进程运行期间有效**：合盖休眠 / 退出应用期间不会补算，也和番茄钟的"绝对 endAt"不是一回事
  （番茄钟靠绝对时间戳可以做到"醒来即知该结束了"，久坐不行——它统计的是用户真的在电脑前的时间）。

## 二点五、已完成 · 5. 剪贴板历史（取自原"待定"，已落地）

### 数据
| 位置 | 说明 |
|---|---|
| `<userData>/clipboard/clipboard.json` | 元数据列表（id/kind/preview/payloadRef/hash/at/pinned/source/truncated）。原子写（tmp + rename） + 180ms 防抖；高频采集也不会抖盘 |
| `<userData>/clipboard/img/<id>.png` | 图片二进制单文件落盘；淘汰时同步删，**绝不冗余** |

容量策略：默认 100 条 **或** 30 天，**先到者为准**；`pinned` 永不淘汰；超龄 / 超量都按 at 升序淘汰；文本 >32KB 截断 + `truncated` 标；同 hash 再复制 **不会新增条目，而是提到队首**。

### 采集
- 主进程 800ms 轮询 `electron.clipboard`；Electron 44 这一版 Clipboard API 全异步（`readText`、`read`、`write`、`writeText` 全部 Promise），tick 用 `inFlight` 串行防重叠。
- 文本直接 `readText`；图片走 `read()` → 查 `ClipboardItem.types` 含 `image/png` → `getType('image/png')` 得 Blob → `arrayBuffer` 写 PNG；第一版仅采 PNG（其它格式提示跳过，避免色彩失真）。
- 默认 **不采图**（`listenImages`），且**隐私立场公之于众**：不假装能识别剪贴板真正来源（那需要 `GetClipboardOwner` P/Invoke，与硬约束冲突），仅给「总开关 / 暂停 / 黑名单 / 不采图默认 / 清空」这一组实用的横切规则。

### UI
- **独立窗口 + 快照式打开**（不在设置页内）——既不撑大设置页，也不抢占宠物窗口的鼠标拦截面积。托盘菜单 + `Ctrl+Shift+V` 切换。
- 键盘：↑↓ 选择 / Home/End 跳到队首尾 / **Ctrl+C 写回剪贴板** / P 置顶 / Del 删（带二次确认）/ Ctrl+L 清空 / Esc 关。双击条目等效于 Ctrl+C。
- "写回剪贴板"第一版**不模拟按键**：没有原生模块只能用 PowerShell `SendKeys`，不可靠、不承诺；面板只把内容落进系统剪贴板，让用户按 Ctrl+V 粘贴。`docs/STATUS.md` 第三部分"剪贴板的诚实的限制"已写明。

### 协议
- `clipboard-img://<id>/img` —— 与 `pet-asset://` 平级的私有协议；`registerSchemesAsPrivileged` + `corsEnabled`（任一缺失，`<img>` 即被标 cross-origin，canvas 之后无法读回）。
- 路径穿越校验：`target !== root && !target.startsWith(root + sep)` 即 403，与 `assetProtocol.ts` 同款。

### 设置接入
- 三项：总开关 / 是否采图 / 关键字黑名单（逗号或换行分隔）。
- 黑名单白名单：`^[\w.*?\-一-鿿]{2,32}$`、≤ 24 条——这是注入面（拼成正则），仍不保证"绝对不记录密码"。
- **存储目录可配置**：`clipboard.storageDir`，先 `path.normalize` 再用正则 `^[^\x00-\x1F*?"<>|]{1,260}$` + `path.isAbsolute` + 长度 ≤ 260。
  ⚠️ **字符类只禁 Windows 文件名系统真不让的字符**——曾误把 `\ / :` 也写进禁止集，导致**任何合法 Windows 路径都过不了**且被静默丢弃（2026-10-15 上午修复）；不合法**永不默默丢**，分原因 `log.warn` + UI 显式报错。
  默认 null = 沿用 `<userData>/clipboard/`。切目录时**不自动迁移旧数据**（保留原目录作为备份，新目录接续采集）。
  切目录前 flush 旧 store，按需重建新 store + watcher；`clipboard-img://` 协议的目录起点跟 currentDir 走，不再写死 `<userData>`。
- **全局快捷键可配置**：两个槽位 —— `clipboard.hotkey`（剪贴板面板）与 `todo.hotkey`（待办面板），Electron Accelerator 格式（`Ctrl+Shift+V` / `Ctrl+Alt+T` 等）；空串 = 禁用该快捷键，仅走托盘与宠物右键菜单入口。
  校验分两路：`sanitizeSettingsPatch` 走 format 正则（白名单修饰键 + 按键字符集），UI 实时反馈走 `tryHotkey`（format + register-noop 试探，区分"格式不合法"与"已被其它应用占用"）。
  注册/注销统一收口在 `services/globalHotkeys.ts`（`setHotkey(slot, …)` / `unregisterAllHotkeys()`），**按槽位分账**：录制待办键不会把剪贴板的键一起解绑（那两个是独立设置项），退出时一次清空全部槽位，避免散在多处的 `globalShortcut.unregister` 漂移。
  before-quit 调 `unregisterAllHotkeys()`，不依赖 app 自己回收。
  ⚠️ 2026-10-15 由 `clipboard/clipboardHotkey.ts` 泛化而来（第二个消费者出现时就该做这件事）：调用点只有 4 处，剪贴板行为逐字不变，设置页截图与重构前一致。
- **录制控件两个设置页共用**：`renderer/settings/components/HotkeyRecorder.vue`（键盘翻译用 `e.code` 认物理键、录制期 `beginHotkeyRecording` 挂起旧键、卸载兜底 `end(null)`）。剪贴板与待办各传自己槽位的三件套，UI 与文案只维护一份。

（原 PRD 的原话是"需要一个 Repository 接口层，将来若要全文检索再评估 SQLite"）。
业务代码（IPC 层、截止提醒）**只依赖接口**，换 SQLite 时只改实现类的替换点（`todo/index.ts::todoRepo()`）。

| 待办字段 | 说明 |
|---|---|
| `title` / `done` / `priority` / `tags` | 优先级三档（低/普通/高）；标签 ≤6 条、每条 ≤16 字 |
| `dueAt` | **绝对时间戳**（与久坐/喝水同口径），null = 不提醒 |
| `order` | 手动排序序号，**拖拽只改这个字段**，不动 `createdAt` |
| `doneAt` | 完成时刻（"已完成"区按它倒序） |
| `notifiedForDueAt` | **"已经就哪个 dueAt 提醒过"**，值就是当时的 `dueAt`。用它而不是布尔值：用户把截止时间从 18:00 改到 20:00 后应当**再提醒一次**，布尔标记做不到 |

便签：`text` / `color`（黄绿蓝粉紫）/ `pinned` / `updatedAt`（置顶优先、其次最近改过），
外加桌面便签用的 `onDesktop`（该不该贴在桌面上）与 `x / y / w / h`（窗口位置与尺寸，屏幕坐标 DIP）。
⚠️ `pinned` 只影响**列表排序**，`onDesktop` 才决定"人在不在桌上"——两件事，不要合并。

落盘是**原子写（tmp + rename）+ 180ms 防抖**，与 `ClipboardStore` 同一套手法；
读取时逐条 `repair`，一条坏记录不会让整份清单读不出来（文件是可被用户手改的）。

### IPC 校验的一个关键区别

`sanitizeSettingsPatch` 的原则是"非法就跳过这一个字段"，**待办不能照抄**：
用户把标题清空再保存，如果只是"跳过 title 字段"，就会得到一个**什么都没发生的假成功**。
所以 `asTodoPatch` 的语义是：**字段没传 = 不改；字段传了但非法 = 整条请求丢掉**，
并且渲染层保存后会回读比对，不匹配就报错（与"剪贴板存储目录静默丢失"那次踩的坑同源）。

另外：空标题、非枚举的优先级/颜色、越界的 `dueAt`（2000–2100 之外）、含空格或超长的标签、
超过 2000 字的便签正文，全部在这一层挡掉并打 warn（**空白便签是唯一放行的例外**，见「桌面便签」）。

### 旁挂小面板（独立窗口）

- **必须独立**：原 PRD 的原话是"独立窗口，**不放大宠物窗口的拦截面积**"。宠物窗口的鼠标拦截区
  是按 `manifest.bounds` 逐像素算的，往上贴任何常驻 UI 都会变成"看着穿过去的地方其实挡住了鼠标"。
- **无边框 + 置顶 + 贴主屏右缘**打开（位置不持久化：这个项目里位置都不是配置项）。
  拖动靠 CSS `-webkit-app-region: drag`（在 header 上），关闭按钮自带 `no-drag`，
  所以不会出现"没有标题栏就关不掉"。
- **窗口必须是 `transparent: true` 的**（2026-10-15 追加，为了让圆角成立）：
  无边框窗口在 Windows 上是**一块直角矩形**，`border-radius` 只作用于渲染内容，四角照旧被窗口底色
  填满 —— 看上去还是方的。想看到"椭圆角"，只能让窗口自己透明、四角露出桌面。
  两条代价都接受：
  1. 透明窗口拿不到系统投影，浮起感得靠 CSS `box-shadow` 补 → 窗口四周留 `PANEL_PAD = 8` DIP 的
     **透明边距**专供投影（`width = PANEL_W + PANEL_PAD * 2`）；
  2. 这圈透明边距**仍然会命中鼠标**（Electron 的命中测试按窗口矩形，不按像素）—— 但那一圈本来
     就是窗口的 resize 热区，"在那儿按下 = 拖边框"并不违和，所以不额外做逐像素穿透。
  渲染层用 `position: fixed; inset: var(--panel-pad)` 与它对齐。⚠️ **TS 的 `PANEL_PAD` 与 CSS 的
  `--panel-pad` 必须同步改**（改一个漏一个，卡片会被窗口裁掉半圈）。
- **面板视觉**（2026-10-15 追加）：`--panel-radius: 14px`；输入框无框化（静止浅灰底、聚焦白底 +
  主题色 ring）；chip 从 3px 方角改**胶囊**；列表换细滚动条。
  主题色一律走 `var(--el-color-primary)`（经 `:root { --accent }` 转发一次，避免七八处各写一遍兜底值）。
  验证不是靠肉眼：见下方自检表的「面板圆角是真的」一行。
- 内容是**未完成的待办**，排序 = 过期 → 今天到期 → 以后 → 没截止；同档内按时间 / 用户拖拽顺序。
- **录入时能顺手定优先级**（2026-10-15 追加）：点录入行左侧的圆点切档。这是"记下来那一刻心里
  就有数"的东西，让用户为它专门跑一趟设置页代价不对等 —— 面板才是高频入口，设置页是低频的。
  - 圆点用「**填充程度 + 颜色**」双编码：空心 = 低、中心实心 = 普通、全实心红 = 高。
    12px 的小圆只有形状和颜色两个自由度，**单靠颜色分不出"低"和"普通"**。
    点一下按 `TODO_PRIORITIES` 走下一档（普通 → 高 → 低 → 普通），所以默认值起手第一下落在"高"上。
  - **记完不重置**：连记三件同优先级的活儿是常态，每条都重点一遍才是打扰；
    当前档位就摆在录入行上，看得见、随时能改。
  - **边界：只动录入，不改已有条目。** 改优先级 / 标签 / 截止时间仍然只在设置页
    —— 面板是常驻窄窗，hover 时再长出一排控件就把它变成小设置页了。
  - 数据层的 `todo.update` 本来就有，这次**只动渲染层**（零 IPC 改动）；窗口之间的 `onChanged`
    双向同步也早就通了，同时开着不会打架。
- **面板为什么不再挂便签**（2026-10-16）：它原本有第二个页签「便签」，理由是"复用面板零成本"。
  那个判断错在**把"能显示"当成了"能用"** —— 便签的用途是"贴在那儿看得见"，被挤进一个 320px 的
  窄窗里跟待办抢纵向空间、看一眼还要先切页签，反而把它最该有的样子弄丢了。现在便签是
  一张一个独立窗口（见下一节），面板回到只做一件事。连 `initialTab` 参数和 `_TAB` 自检参数都
  一并删干净了 —— 面板不再有页签，留着就是误导。
- **全局快捷键唤起**（2026-10-15 追加）：`todo.hotkey`，默认 `CommandOrControl+Alt+T`，
  在「待办与便签」设置页里录制（控件与剪贴板设置页共用，见「已完成 · 5」的 `HotkeyRecorder.vue`）。
  **为什么不用更顺手的 Ctrl+Shift+T**：那个组合在浏览器里是「恢复刚关掉的标签页」，
  全局注册会把它从**所有**应用手里抢走，用户只会以"浏览器坏了"的形式感知到；Alt 组合在
  Windows 上几乎没有系统级占用。留空 = 禁用（托盘 / 右键菜单 / 设置页入口照旧）。
  设置改完立即热生效（走 `applySideEffects` 重新注册），旧键同时被释放。

### 桌面便签：一张便签 = 一个独立窗口（2026-10-16）

**这一节推翻了 2026-10-15 的"不做独立便签墙窗口"决策。** 当时的推演是"另开一个透明底、
卡片散落桌面的窗口要付三笔成本"——**那三笔成本是针对"一个大窗里画多张卡片"这种实现**，
而这个实现本身就是错的：铺满工作区的透明窗口要鼠标穿透，只能逐像素切换，而高频切换穿透
会让全系统鼠标卡死（技术约束 3）。换成"一张便签一个窗口"之后，三笔成本全部消失：

| 当时担心的 | 独立窗口下为什么不存在 |
|---|---|
| 与宠物窗口的 z 序不可控 | 宠物是 `screen-saver` 层、便签是默认的 `floating` 层，层级**天生分开**，不取决于最后调用谁 |
| 透明区吃鼠标 | 每张纸就是一个自己的小窗口，纸与纸之间的空隙**不属于任何窗口**，鼠标自然穿过去 |
| 抢焦点 | 只有「记一条便签」这一次主动 `focus()`；其余（含启动时恢复一屏）一律不抢 |

"位置持久化"那条破例也认了：**便签必须记位置**，不然每次启动所有纸条都会叠在同一个点上。
这与"面板位置不持久化"不冲突 —— 面板是一个窗、位置随手拖；便签是一组窗、位置是内容的一部分。

实现要点（`src/main/notes/index.ts` + `src/renderer/src/notes/` + `src/renderer/notes.html`）：

- **数据是唯一真相，窗口只是它的投影**：`syncDesktopNotes()` 幂等地对账 —— 数据里
  `onDesktop: true` 而没开的补开、没贴却还开着的关掉。任何开关窗都不许绕过它
  （那就是"两份状态互相追赶"的开局）。启动恢复、IPC 写操作收尾、托盘"全部收起"走的都是它。
- **老数据缺 `onDesktop` 一律按 `false` 恢复** —— 升级不该让用户桌面上凭空冒出一排纸条，
  要贴哪几张由他自己点。位置四个数**缺一不可**：半组脏值（有 x 没 y）会让窗口落到屏幕外，
  用户只会觉得"我的便签不见了"。
- **第一次现身就把落点写回数据**（`ready-to-show` 里 `flushRect`），不能只等拖动的 `moved` 事件 ——
  否则重启时每张都要重新挑空位，而挑空位依赖创建顺序（顺序又来自"最近改过优先"），
  用户会看到自己的便签"每次开机都自己换地方"。拖动 / resize 期间 350ms 防抖落盘，
  关窗前再补一次（"拖完立刻关"不会丢最后一帧）。
- 挑空位：从**工作区右下角**起、先往上排再往左挪一列，避开已存在的便签窗口矩形；
  恢复时位置要**夹回工作区**（换过显示器、拔过外接屏之后，老坐标会落在屏幕外）。
- 窗口：`transparent` + `frame: false` + `alwaysOnTop` + `skipTaskbar`（20 张便签不该是 20 个
  任务栏图标）+ `hasShadow: false`（影子自己用 CSS 画）。默认 220×180、可拖边 resize；
  上限 `NOTE_DESKTOP_MAX = 24` —— 每张是一个渲染进程，得有个兜底；撞上限的会被改回"不贴桌面"
  并打 warn，**不能让"数据说贴着、桌面却看不见"**。
- **两个按钮分工**：`⌄` 收起（`onDesktop: false`，**位置保留**，设置页随时能再贴出来）、
  `✕` 删除（连内容一起，不可恢复）。用户明确要的就是这两个动作分开。
- 正文**可以直接在便签上改**：输入防抖 300ms 写回；`editing` 期间不接受外部广播覆盖
  （写回会广播给所有窗口，包括自己 —— 无脑覆盖会把用户正打的一半字顶掉）。
- **空白是合法状态**：`asNoteText(…, allowEmpty)` 只对便签放行 —— 桌面便笺的语义就是
  "写空了也留着"，`repairNote` 也不再因空正文丢记录。托盘的「记一条便签…」靠它一次落一张空纸、
  光标已经在里面（URL 带 `?focus=1`，渲染层读到就 autofocus）。
  ⚠️ 这与**待办标题**的口径不同，那边空标题仍然直接拒。
- **入口三个**：设置页便签区的「贴到桌面 / 收起」（挑哪几张贴出去，卡片时间行会标「已贴桌面」）、
  托盘「便签」子菜单（记一条 / 全部贴到桌面 / 全部收起 / 便签管理）、宠物右键「记一条便签…」。
- 纸色 `NOTE_SKIN` 仍在 `src/renderer/src/common/note-skin.ts`，设置页与便签窗口**两处共用**。
- **换纸色在便签窗口顶部那排圆点上**（2026-10-16 加）：点一下即换，改的是 `updateNote` 的
  一个字段 patch（只带 `color`、不动正文），所以这里**不需要**先 `flushSave` —— 两个字段互不干扰。
  圆点取 `NOTE_SKIN[c].dot`，是比纸面 `bg` 饱和得多的"代表色"：五个淡色点铺在一张淡纸上，
  谁也认不出谁。当前色靠**半透明深色**描边标出（白色描边在黄纸上会糊掉）。
  圆点必须 `-webkit-app-region: no-drag`（整张纸是拖动区，不标就点不动）；
  窗口被拖到最窄时先挤左边的拖动把手 `⠿`，别把色点 / 按钮挤出台面。

### 实机自检（2026-10-15；桌面便签相关于 10-16 追加）

新增几个开发期钩子（与 `HPY_CAPTURE_SETTINGS` 对称）：

- `HPY_CAPTURE_TODO_PANEL=<png>`（+ `_FOCUS=1` 验"聚焦快速录入框"、`_EVAL=<js>`）
- `HPY_CAPTURE_NOTE=<png>`（+ `_TEXT` / `_COLOR` / `_FOCUS=1` / `_EVAL=<js>`）—— 临时贴一张便签、
  截图、删掉。它走的是**真实入口** `createNoteOnDesktop()`（托盘「记一条便签」用的同一个函数），
  而不是在钩子里自己拼一遍 `addNote` —— 否则验的是一条只存在于钩子里的旁路。
  这张便签截完即删，**用户自己的便签一条都不动**（所以它不像面板的 `_EVAL` 那样需要 seed / restore）。
- `HPY_CAPTURE_SETTINGS_WAIT=<选择器>`（等哪个标志物出现再截，默认 `.pet-card`）
- `HPY_CAPTURE_SETTINGS_SCROLL=<选择器>`（截图前滚过去，页面长了以后下半部分截不到）
- `HPY_CAPTURE_SETTINGS_EVAL=<js>`（**唯一能端到端验证"渲染层 → preload → IPC → 落盘 → 广播回渲染层"的手段**）
  ⚠️ 代码是**内联**进 `executeJavaScript` 的脚本里的，不是页面里调 `new Function`——
  页面 CSP 是 `script-src 'self'`（没有 `unsafe-eval`），页面自己发起的 eval 会被拦，
  而 DevTools 通道里的代码不受 CSP 约束。

> ⚠️ **两种 `_EVAL` 的写法不一样，别互相抄**：
> - `HPY_CAPTURE_SETTINGS_EVAL` 是**函数体**（被内联进 `await (async () => { … })()`），
>   直接写 `location.hash = '#/todo'; await …; return {…}` —— **不要**再包一层 IIFE，
>   包了内层的 `return` 传不出来，日志里只会看到一个空的 `{}`（踩过）；
> - `HPY_CAPTURE_TODO_PANEL_EVAL` / `HPY_CAPTURE_NOTE_EVAL` 是**完整脚本**（直接
>   `executeJavaScript` 执行），那边的 `(async () => {…})()` 才是对的。
>
> ⚠️ 便签窗口截图必须等 **`ready-to-show`**，不能等 `did-finish-load`：透明窗口在真正显示之前
> **没有可截的帧**，这时 `capturePage()` 会抛 `UnknownVizError`（第一次写就踩到了）。
>
> `HPY_CAPTURE_TODO_PANEL_EVAL` 在诊断脚本之后、截图之前再跑一段渲染层脚本，返回值同样打进日志。
> 面板此前只有"看一眼"的证据，从外面看不出"操作真的落盘了没有"；`_EVAL` 补上了这条
> （例：点圆点 → 填标题 → 回车 → 读回那条的 chip）。⚠️ 它**会真写数据**，
> 必须配 `.tmp/seed-notes.mjs seed|restore` 兜住用户数据。

## 三、待定（方案已想清楚，先不做）

### 1. 剪贴板历史 —— 已被提升到「已完成 · 5」（见上）。【2026-10-15 落地；2026-10-15 加轮：自定义存储目录 + 自定义全局快捷键】

**架构已定**，未来要做的是补全：
- 多设备 / 多机同步（要 IPC 安全层，目前没有）
- 全局快捷键被占用时的回退（在 `globalShortcut.register` 失败时已 log.warn，但可以再列出可改键位）
- 文件类（kind: 'files'）：Electron Clipboard 没"files"槽，目前退化文本（文件名拼串）；要做需要 `clipboard.write({...bookmark})` 之外的方案
- 「存为待办」入口：待办便签已于 2026-10-15 落地（见「已完成 · 6」），数据层两边都是独立的
  —— 这个入口现在**有地方可接了**，但仍未做。做的时候只做"把这条剪贴板内容新建成一条待办"，
  **不要把两张表合并**

设计过程留档（最早一轮的原始方案，**不再作为待做**——已被上面 §5 取代）：

**现状**：只能保存"最近复制的一项"。**目标**：保留最近 N 条，随时翻出来挑一条用。

**数据模型**

| 字段 | 说明 |
|---|---|
| `id` | 自增或 uuid |
| `kind` | `text` / `image` / `files` |
| `preview` | 列表里显示的一行摘要（文本截断、图片缩略图路径、文件名的逗号串） |
| `payloadRef` | 文本直接内联；图片/大文本落文件，这里只存路径 |
| `hash` | 内容哈希，用于去重。**同 hash 再次复制 → 提到最前，不新增一条** |
| `at` / `pinned` / `source` | 时间 / 置顶不淘汰 / 尽力而为的来源标识 |

**容量与存储**
- 默认保留 **100 条或 30 天**（先到者为准），超出按时间淘汰；`pinned` 的永不淘汰。
- 文本单条上限 32KB，超过只存头部 + 标记"过长未完整保存"。
- 图片走 PNG 存到 `userData/clipboard/`，**绝不塞进 settings.json**（会把配置文件撑爆，且每次写盘都变慢）。
- 删除策略：淘汰时同步删文件，避免目录里留下孤儿。

**采集**
- 已落地：每 800ms 一次轮询走 `clipboard.readText()`，图片走 `clipboard.read()` → `ClipboardItem.getType('image/png')`。
- 文本走 SHA-1 去重；超 32KB 截断打 truncated；图片 PNG 单文件落 `img/`。默认不采图。
- **不用全局键盘钩子**（同前置；与硬约束冲突）。

**隐私（这块要诚实）**
- 不假装能识别剪贴板真正来源（要 `GetClipboardOwner` P/Invoke）。能给的就这些：总开关 / 暂停 / 黑名单 / 默认不采图 / 清空。
- 黑名单字符集收紧到 `[\w.*?\-一-鿿]{2,32}`、≤ 24 条（注入面）。**仍不承诺"绝对不记录密码"**。

**交互**
- 独立窗口 + 快照式打开（不在设置页内）。托盘菜单 + `Ctrl+Shift+V` 切换。
- 键盘：↑↓/Home/End 选择，**Ctrl+C 写回**，P 置顶，Del 删（二次确认），Ctrl+L 清空，Esc 关。
- **诚实的限制**：第一版**不模拟按键**（要 `SendKeys` 才不靠谱）。面板把内容落进系统剪贴板，让用户 Ctrl+V 自己粘。

**与待办便签的关系**
- 待办是"值得留下的"，剪贴板历史是"刚才那几下"——生命周期和淘汰规则完全不同，**不要合并**。
- "存为待办"的入口**仍未做**：数据层已就位（见「已完成 · 6」），做的时候只是"新建一条待办"，
  **不要合并两张表**。

## 四、技术约束（改代码前先看）

1. **npm 脚本必须走 `tools/electron-vite-run.mjs`**：宿主环境预设了 `ELECTRON_RUN_AS_NODE`，
   Electron 看到该变量（空串也算）就退化成纯 Node，主进程必崩。
2. **主进程是 CJS**（`package.json` 无 `"type": "module"`），因为 `sandbox: true` 要求 preload 是 CJS；
   因此不能用 pure-ESM 包（如 electron-store v12）做静态 import。
3. **不引原生模块**（无 electron-rebuild / VS Build Tools 依赖）。
   需要系统级能力时，退路是**常驻 PowerShell 辅助进程**（见 `foregroundProbe.ts`），
   并且只用反射载入系统程序集，不用 `Add-Type`。
4. **穿透切换只在边沿发生**：去重 + 进入立即 / 离开延迟 80ms。
5. **`pet-asset://` 必须开 CORS，且 `<img>` 必须设 `crossOrigin='anonymous'`**，两者缺一 canvas 就被污染。
6. **状态同步方向**：主进程是"意图"来源，渲染进程是"动画"执行者；
   渲染层只上报自身短动画结束，不自行决定业务状态。
7. **凡是"先读 A 的状态、再写 A 的值"的顺序，都要先写后读**（踩过：走动方向下发早于朝向写入 → 倒着走）。
8. **提醒只能经由 `notifier` 往外发**，任何功能都不要自己弹通知 / 自己喊宠物说话。
   "免打扰""沉浸时别打扰"是横切的，各自为政必然漏掉某一处。
9. **主进程里凡"过了多久"的判断，都存绝对时间戳，不要累加计数器**。
   `setInterval` 在休眠 / 满载时会漏拍漂移；存时刻则永远精确（久坐的 `activeSince`、喝水的 `nextWaterAt`）。
10. **开发期加速的阈值之间要保持正确的大小关系**：`HPY_FAST_REMIND` 里"离开判定"（45s）必须大于
   "久坐提醒"（20s）与"喝水提醒"（25s）。最初把离开判定设成 8 秒，结果稍一停手就被判离开、
   久坐计时反复清零，**加速模式自己变得不可测**。
11. **`sanitizeSettingsPatch` 是设置写入的唯一入口**（进程名白名单 `^[a-z0-9._*?-]{1,64}$`、≤8 项）。
   新增设置项必须过它，否则 IPC 白名单形同虚设。
12. **不要用 `app.setName()`**：它决定 `userData` 路径，改了等于让老数据搬家。
   通知头顶那行**应用署名**由 Windows 按 AUMID 解析开始菜单快捷方式得到，粒度是"应用"不是"通知"
   —— dev 态没有匹配的快捷方式就回落成 `Electron`，打包后自动变 `productName`，
   **改不成宠物名**；想让提醒带上宠物名，走通知**标题**前缀（`notifier` 已在做）。
13. **可见性只有一个收口 `setPetVisible()`，且它必须顺手记下"意图"**（`desiredVisible`）：
   窗口是用 `show: false` 创建的，`ready-to-show` 才第一次真正显示，在此之前调 `hide()` 是空操作。
   所以 `ready-to-show` 只能"按意图露面"，**不能无条件 `showInactive()`** ——
   否则 `settings.petVisible=false` 的重启、以及开机自启的"静默 3 秒"都会被它抹掉
   （2026-10-15 实机踩到并修复；回归判据：日志里该出现 `宠物窗口按启动意图保持隐藏（不显示）`
   且**不出现** `宠物窗口已显示`）。
14. **新窗口 = 新渲染入口**：`electron.vite.config.ts` 的 `renderer.build.rollupOptions.input`
   加一条，同时补 `src/renderer/<name>.html`。CSP 按需写 —— 不引 Element Plus 的窗口
   （宠物 / 剪贴板面板 / 待办面板）不要加多余来源。
15. **`npm run build` 前先停 dev**：dev 占着 `out/`，vite 的清理会卡在 `safe-delete` 上超时失败
   —— 这不是代码问题，别去改代码。
16. **`menu.popup({x, y})` 的坐标是窗口客户区坐标**，不是屏幕坐标；宠物右键菜单**不传坐标**
   （交给系统按光标定位），传了反而会偏。
17. **宠物窗口里除序列帧以外的 UI 都要放在 `.pet-stage` 之外**：stage 整层套了
   `scale(var(--pet-scale))`，放进去就会跟着 `petScale` 一起缩放 —— 文字类 UI 会随宠物调小而变得看不清
   （气泡踩过：宠物 75% 时 12px 的字只剩 9px）。要贴宠物定位就自己按 `petScale` 换算锚点，
   字号保持 DIP 绝对值。
18. **开发期自检钩子的四个坑**（跑之前先对一眼，否则会得到"功能坏了"的假结论）：
   - `HPY_CAPTURE_SETTINGS_EVAL` 的代码是**内联进 `executeJavaScript` 字符串**的，
     不能在页面里 `new Function` —— 页面 CSP 是 `script-src 'self'`（无 `unsafe-eval`），
     而 DevTools 通道不受 CSP 约束；
   - Git Bash 会把 `VAR=/todo` 当路径改写成 `D:/xxx/todo`，传路由 / 选择器一律加 `MSYS_NO_PATHCONV=1`；
   - `npm run dev` 构建约 25s，验"到点提醒"时到点时刻要留足窗口，否则会被判成"启动前已过期"而静默跳过；
   - 跑之前先清残留 electron（否则「已有实例在运行」直接退出、dev 死占 5173）；
     探针日志的**行序 ≠ 事件序**；往 `<userData>` 塞自检数据前先备份，验完还原。
